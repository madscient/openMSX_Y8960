# 振り返り

目的は責任の追及ではなく、原因の分析と再発防止。
対策として書いてよいのは次のいずれかに当たるものだけ。

- 判断の瞬間に見える情報を変える
- 失敗が黙って通らない仕組みにする
- 判断そのものを要らなくする

「以後注意する」は対策ではない。

---

## 2026-09-08 〜 09 — Y8960 対応の立ち上げ

このセッションでやったこと: 調査 → ビルド環境構築 → buppu3 実装の載せ替え →
OPLL I/O enabler → OPL2EX + ADPCM-B → SSGS → 公開。

### 1. AI 側の失敗

#### 1.1 テストで GUI ウィンドウを開いた（最も影響が大きい）

openMSX を検証で起動するたびにウィンドウが出ていた。ユーザーは同じマシンで
並行作業しており、**キーボードフォーカスを奪って入力が混ざる事故**になりうる。
指摘されるまで気づかなかった。

原因は、GUI アプリを繰り返し起動する前に「これはウィンドウを出すのか」を
一度も確かめなかったこと。`-testconfig` は出さないが `-script` は出る、という
違いも見ていなかった。

**対策（実施済み）**: ルートの `CLAUDE.md` §5 に、スクリプト先頭へ
`set renderer none` / `set sound_driver null` を置くことと、その理由を書いた。
ルート直下は常に読み込まれるので、判断の瞬間に見える。
実際にウィンドウが出ないことは `MainWindowHandle` が 0 になることで確かめる、
という検証方法も併記した。

#### 1.2 `msbuild ... | tail` で失敗を握り潰した

3rdparty のビルドが 2 エラーで落ちたのに、パイプラインの終了コードが `tail` の
ものになるため `&&` が通り、壊れた 3rdparty の上に本体をリンクした。
出てきたリンクエラーを「本物の問題」として報告してしまった。

**対策（実施済み）**: `doc/fork/build/README.md` §3 に明記。
さらに `CLAUDE.md` §6 に 1 行足した。ビルドは毎回ここを見るので、
判断の瞬間に見える位置にある。

#### 1.3 `thirdparty_download.py` を不要に走らせてソースを壊した

ブランチを切り替えたから再取得が要る、と確かめずに決めた。このスクリプトは
既存ソースを毎回 `rmtree` してから展開し直す仕様で、`PermissionError` で
中断して SDL2 が欠けた状態になった。

**対策（実施済み）**: `build/README.md` §2.5 に「要求ライブラリの版が
変わったとき以外は走らせない。版は `build/packages.py` で確認できる」と書いた。

#### 1.4 「OPLL の番号が RTL と逆」という誤った断定

localparam の**名前**だけを見て食い違いだと判断し、**確認済み**の印を付けて
文書に書いた。実際にはアドレスと回路の対応は一致していた。
ユーザーの「7C/7D がプライマリと思いますが RTL はどうなってますか」で発覚した。

`opll.v` は読んでいたが末尾だけで、`bus_address[1]` が回路を選ぶという
肝心の 2 行を見ていなかった。**行番号を引用していたのに間違えた**のが問題で、
引用したのが挙動を決める行ではなく名前を定義する行だった。

**対策（実施済み）**: `CLAUDE.md` §4 に、食い違いを主張するときは
名前ではなく挙動を決めている行まで辿ること、と足した。

#### 1.5 SSGS の欠落範囲を過大に見積もった

YMZ705 のデータシートから「ADPCM 8 音とシーケンサ 2 系統が丸ごと欠けている」と
書いた。実際に Y8960 が使うのは SSG 互換部だけだった。
チップの全機能を、その製品が使う範囲だと読み替えてしまった。

#### 1.6 ヒアドキュメント経由でバックスラッシュを壊した

`py - <<'EOF'` に `\v` を含む内容を渡し、垂直タブ (0x0B) に化けて文書の 3 行が
壊れた。さらに**壊れた文字列を grep しても空振りした**（制御文字が間に入るため）
ので、自分の検査が「残存なし」と誤報した。直そうとした置換が無関係な 1 行を
潰しもした。

**対策（実施済み）**: `doc/fork/tools/check-docs.py` が制御文字を走査する。
バックスラッシュを含む内容は `Write` で書く、というのは規則なので対策に数えない。
**検査が黙って通らないようにした**のが対策である。

#### 1.7 検査器の検索語を、検査器自身に書こうとした

漏らしたくない語（ユーザー名・マシン名・ROM の置き場所）を検索語として
ファイルに直接書くと、**検査器そのものが漏洩源になる**。
第 3 項の点検は「本文に無いか」を見るが、**点検器自身が本文の一部である**。

これは誤検知として表に出る。検査器が自分に当たったとき、
除外して黙らせるのは症状を消すだけで、語はそこに残る。
**当たった理由を先に考えること。**

**対策（実施済み）**: 検索語をファイルに書かず、実行時に組み立てる。

- ユーザー名・マシン名は環境変数から
- ROM の置き場所は `derived/` のジャンクションのリンク先を解決して得る
  （フルパスで照合する。basename は `MSX` のような一般語になり全文に当たった）
- 別マシンで書かれたものは上の 2 つでは捕まらないので、
  誰の名前も含まない「ホームディレクトリの絶対パス」の一般形も併せて見る

副産物として、どのマシンでも書き換えずに効くようになった。
**説明のコメントに例示パスを書かないこと。** これも自分に当たる。

#### 1.8 コミット trailer の書き損じ

`Co-Authored-By` のアドレスを打ち間違えた。push 前の自前点検で捕まえて
amend したので外には出ていない。**点検が働いた例**。

### 2. 人間側の指示・判断

評価の目的は、人間が直接動かせるのは人間の行動だけだからであって、
AI の失敗を人間に防がせるためではない。**AI のために人間の労力を増やすのは
本末転倒**なので、費用が小さく効果の大きいものだけ挙げる。

#### 2.1 無駄を生んだ点

**「SSGS の実装は EPSGemuEngine にあります」が 2 回とも外れた。**
1 回目はリポジトリに無く、2 回目は「`extern/ay8910/ay8910.cpp` に埋まっている」
との指示だったがそこにも無かった。実際は別マシンで push 漏れしていた。
探索に 5 サイクルほど費やした。

ただし損失は限定的だった。**こちらが指示を鵜呑みにせず実際に見に行った**ため、
「無い」と早期に報告できた。もし信じて設計を進めていたら遥かに高くついた。

費用の小さい改善案: **未確認の心当たりは「確認していないが」と添える。**
3 語で済み、こちらの動きが「深く探す」から「まず存在確認」に変わる。
指示の正確性を上げる要求ではない。

**RTL を一次情報の最上位に置く前提**を、こちらが早期に置いてしまった。
これは指示ではなくこちらの判断だが、`RTL は WIP のプレースホルダ` という
事実が中盤で出てきて覆り、DCSG のアドレス実装と差し戻し、OPLL enabler の
分析の枠組み、SSG の設計方針が影響を受けた。
ただしこの事実はユーザーも HRA さんから聞くまで知り得なかったので、
**指示の欠陥ではなく情報の非対称**である。

#### 2.2 大きく効いた判断

- **buppu3/openMSX の存在を早期に教えたこと。** これが最大の節約だった。
  こちらは単一デバイス方式で一から実装する計画を立てており、そのまま進めば
  2000 行近くを書いて捨てることになっていた
- **GUI の件を溜めずにその場で止めたこと。** 繰り返す前に直せた
- **設計の分岐で即断したこと**（ymfm を入れない / V9968 を外す / パンポットは
  案 B / SSGS は自前実装）。どれも保留されていたら止まっていた
- **公開前に身元と帰属表示を確認させたこと。** fork はオブジェクトを親と共有し、
  push したものは後から消せない。順序が逆なら取り返しがつかなかった
- **誤りを質問の形で突いたこと**（OPLL の 7C/7D）。断定で否定されるより、
  こちらが根拠を辿り直す動きになった

#### 2.3 仕様が動くことについて

DCSG のアドレス、OPLL の enabler、SSG → SSGS、ミキサーのアドレス、
リセット時の I/O 状態。いずれも途中で変わった。これは WIP の相手をしている
以上、指示の質の問題ではない。

効いたのは、**計画文書に「前提」を明記して、覆ったらその場で訂正を書く**
という運用だった。`implementation-plan.md` §8 に訂正が 3 件残っている。
これは続ける価値がある。

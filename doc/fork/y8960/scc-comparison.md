## 1. 要約

- 発音そのもの（波形の読み出し、周波数、音量の掛け方、サンプルレート）は 3 者とも同じコード
- Yamanooto の SCC は **SCC+ の互換モード**（`Mode::Compatible`）で始まり、モードレジスタで SCC+ モードに切り替わる。Konami SCC と
  Y8960 は **SCC 専用**（`Mode::Real`）。音に効く差は、変形レジスタの番地、変形レジスタの bit7、波形 5 の独立（§4）
- 定位: Konami SCC はモノラル、Yamanooto は固定の擬似ステレオ、Y8960 はチャンネルごとに書ける定位（§5）
- 音量: 同じ `<volume>` なら、Yamanooto の SCC は電力でモノラルの 2 倍（+3dB）。Y8960 には SCC の音量レジスタとマスター音量がある（§5）
- バンク番号: Konami SCC は 8 ビット、Yamanooto は 10 ビット（オフセット付き、8MB フラッシュ）、Y8960 は 6 ビット（ROM 16・RAM 16・SCC）（§2）
- SCC の窓: Konami SCC は 9800-9FFF だけ。Yamanooto はほかに SCC+ モードの B800-BFFD と、0000-3FFF のミラーにも出る。Y8960 は 4 つの
  region のどれにも出せる（§3）

## 2. バンク ROM（マッパー）

| 項目 | Konami SCC（基準） | Yamanooto | Y8960 |
|---|---|---|---|
| バンクの大きさと数 | 8kB × 4（4000-BFFF） | 同じ | 同じ |
| バンクレジスタの番地 | 5000-57FF / 7000-77FF / 9000-97FF / B000-B7FF | 同じ。ミラーの D000-D7FF / F000-F7FF / 1000-17FF / 3000-37FF でも書ける（下の「書き込みのミラー」） | 同じ（互換モード）。RAM モードでは 48FC-48FF（100h ごとに 4FFF までミラー）に移る |
| バンク番号の幅 | 8 ビット。ROM の大きさで折り返す。512kB を超える ROM には警告を出す | 10 ビット。書いた値にオフセット（`(OFFR << 2) \| CFGR の SUBOFF`）を足す。フラッシュは 8MB | 下位 6 ビット。#0-#15 は ROM、#16-#31 は RAM、#32-#62 は #0-#30 と同じ、#63 は SCC |
| バンクレジスタの読み出し | できない | できない | できない |
| リセット後のバンク | 0, 1, 2, 3 | 0, 1, 2, 3（オフセットも 0） | 0, 1, 2, 3（互換モード） |
| 読み出しのミラー | 4000-7FFF を C000-FFFF に、8000-BFFF を 0000-3FFF に | 同じ（アドレスの bit15 を反転） | 同じ |
| 書き込みのミラー | 無い。5000 未満と C000 以上への書き込みは捨てる | **ある**。書き込みもミラーしてから判定する。たとえば 1000-17FF に書くと 8000 の region のバンクが替わる | 無い。4800 未満と C000 以上への書き込みは捨てる |
| ミラーが CPU から見える構成 | `-romtype SCC` で挿したとき（0000-FFFF に置かれる）。`scc.xml` は 4000-BFFF だけ | 拡張定義が 0000-FFFF | `HRA_Y8960.xml` は 4000-BFFF だけ。`-romtype Y8960Cartridge` で挿すと 0000-FFFF（§7 の 1） |
| 書き込みの行き先が変わる条件 | 無い | 7FFF（ENAR）の WREN でフラッシュへの書き込みになり、そのあいだバンクも SCC も書けない | RAM モード（48FB の bit0）では、6000-BFFF の RAM バンクに書ける |
| 独自のレジスタ | 無い | 7FFC-7FFF（ENAR・OFFR・CFGR・FPGA との通信）。ENAR の REGEN で現れ、読める。ミラーしない | 7FE0-7FFF（音源・ミキサー・Enabler）。読めるのは 7FFF だけ。region 3 が SCC のとき、RAM モードで region 3 が RAM バンクのときは無い |
| ほかの動作 | 無い | CFGR の K4 で Konami4 の形（SCC は無い）、MDIS でバンクを固定、ROMDIS でフラッシュを FFh に | 無い |
| `romblocks` の番号 | `setRom` に渡したブロック | 独自（`bankRegs` の 10 ビット） | 16 で割った余り。RAM バンクも ROM の番号に見える（`implementation-plan.md` §9.7） |

## 3. SCC の窓

| 項目 | Konami SCC（基準） | Yamanooto | Y8960 |
|---|---|---|---|
| 窓を出す条件 | 9000-97FF に書いた値の下位 6 ビットが 3Fh | 9000 のバンクの**書いた値そのもの**（オフセットを足す前）の下位 6 ビットが 3Fh。K4 では出ない | その region のバンクの下位 6 ビットが 3Fh。RAM モードの region 2（4000-5FFF）だけは出さない |
| 窓の番地 | 9800-9FFF | 9800-9FFF。SCC+ モードでは代わりに B800-BFFD（B000 のバンクの書いた値の bit7 が条件） | その region の上 2kB。5800-5FFF / 7800-7FFF / 9800-9FFF / B800-BFFF |
| ミラーの番地の窓 | 出ない | 出る（1800-1FFF。SCC+ モードでは 3800-3FFD） | 出ない |
| 窓のある region の下 6kB | ROM（書いた値を ROM の大きさで折り返したブロック） | フラッシュ（書いた値 + オフセットのブロック） | ROM の #15（63 を 16 で割った余り） |
| 窓の中で SCC に届かない書き込み | 無い | 無い | 9900-9904 は定位のレジスタで、書き込みは SCC に届かない。読むと SCC（波形 1 の 00-04 のミラー）が返る |
| SCC+ のモードレジスタ | 無い | BFFE-BFFF（ミラーの 3FFE-3FFF も）。見るのは bit5 だけ | 無い |

Yamanooto の SCC+ モードを SCC+ カートリッジ（`src/sound/MSXSCCPlusCart.cc`）と比べると、窓の終わりが BFFF ではなく BFFD で、
モードレジスタの bit4 と bit0-2（RAM の書き込みの許可）を見ない。

Y8960 の窓が 4 つの region に出るのは、このフォークで決めた拡張（`implementation-plan.md` §3.8.1 の規則 1）。RTL にあるのは
9800-9FFF と、RAM モードの 7800-7FFF だけ。

出典: `RomKonamiSCC.cc:71-125`、`Yamanooto.cc:105-118, 142-182, 258-279`、`Y8960Cartridge.cc:200-216, 250-300`、`MSXSCCPlusCart.cc:114-115, 251-282`。

## 4. SCC のモード（音に効くもの）

Konami SCC と Y8960 は `Mode::Real` のまま変わらない。Yamanooto は `Mode::Compatible` で始まり、モードレジスタの bit5 で `Mode::Plus`
に移る。リセットで `Compatible` に戻る。

| 項目 | Real（Konami SCC・Y8960） | Compatible（Yamanooto の既定） | Plus（Yamanooto の SCC+ モード） |
|---|---|---|---|
| 波形 5 | 波形 4 と共有。波形 4 に書くと両方が変わる | 同じ | 独立していて、書ける |
| 周波数と音量の番地 | 80-9F | 80-9F | A0-BF |
| 変形レジスタの番地 | E0-FF | C0-DF | C0-DF |
| 変形レジスタの番地を**読む**と | FFh を書いたことになる | 同じ | 同じ |
| 変形レジスタの bit7（ch4・ch5 の回転） | 効く | 捨てる | 捨てる |
| bit6 だけを立てた回転で、ch4 の回転の速さを決める周期 | ch5 の周期 | ch5 の周期 | ch4 自身の周期 |
| A0-BF の読み | FFh | 波形 5（波形 4 の写し） | FFh |
| デバイスの説明 | "Konami SCC" | "Konami SCC+" | "Konami SCC+" |

チャンネルの番号は 1 から数える。

変形レジスタの番地が違うので、Konami SCC の番地（98E0-98FF）に書くソフトは、Yamanooto の既定のモードでは変形が効かない。
逆に Yamanooto の番地（98C0-98DF）に書いても、Konami SCC と Y8960 には効かない。

出典: `SCC.cc:119-123, 177-266, 289-341, 356-373, 427-465`、`Yamanooto.cc:39, 273-279`。

## 5. 音量と定位

発音のあと、ミキサーに渡るまでの差。

| 項目 | Konami SCC（基準） | Yamanooto | Y8960 |
|---|---|---|---|
| デバイスの形 | モノラル | ステレオ（`setBalance()` で 5 チャンネルに定位を与えた） | ステレオ（`enableSetChannelFactors()`） |
| 各チャンネルの左右の係数 | 無し。ミキサーがモノラルを左右に √½ ずつ配る | ch1 は中央で 1.0 / 1.0、ch2・ch4 は 1.292 / 0.574、ch3・ch5 は 0.574 / 1.292（バランス ∓0.67） | 定位レジスタ 9900-9904 で書ける。等パワー（cos / sin）。既定の 128 で 0.707 / 0.707 |
| チャンネルの定位を変える手段 | 無い | 無い。固定で、切り替えも無い（ソースの TODO に「SCC stereo mode」） | 定位レジスタ。0 は 1 と同じ左端 |
| 音量レジスタ | 無い | 無い | SCC の音量 7FFA とマスター 7FFE。0 で無音、1-127 は 1/128 刻みの直線、bit7 が立てば 1 |
| `<volume>` | `-romtype SCC` は 9000、`scc.xml` は 11500 | 9000 | 30000（OPM の大きさ）。SCC はその 7509/30000 |
| 左右それぞれの振幅（`<volume>` の単位、既定の状態） | 9000 × 0.707 = 6364（`scc.xml` は 8132） | ch1 は 9000。ch2・ch4 は L 11631 / R 5170 | 7509 × 0.707 = 5310 |
| 電力をモノラルの `<volume>` に直した値 | 9000（`scc.xml` は 11500） | 12728（どのチャンネルも同じ） | 7509 |
| `-romtype SCC` との差 | 0dB（`scc.xml` は +2.1dB） | +3.0dB | −1.6dB |

openMSX のデバイスごとの音量とバランスの設定は 3 者とも効く。

計算の根拠:

- ミキサーは、モノラルのデバイスを左右に `volume × √½` ずつ配り、バランス 0 のステレオのデバイスは左を左へ、右を右へ `volume × 1`
  で渡す（`MSXMixer.cc:726-767`）
- `setBalance(b)` の係数は `√(1−b)` と `√(1+b)`。中央で 1.0 / 1.0 になり、左右の電力の和はどの b でも 2（`SoundDevice.cc:114-124`）。
  モノラルの左右の電力の和は 0.5 + 0.5 = 1 なので、Yamanooto の SCC はどのチャンネルも電力でモノラルの 2 倍
- Y8960 の中央は 0.707 / 0.707 で、電力の和は 1。モノラルと同じ（`Y8960Cartridge.cc:115-125`）
- 3 者とも SCC の増幅率は 1/128（`SCC.cc:343-346`）で、上の数にさらに掛かる

Yamanooto の音量の経緯（コミットから読めること）: PSG の 3 倍（`Yamanooto.cc:43-46`）は、2024-12-23 に実機の比較から入った
（`1763b61aa`）。SCC の定位はその後の 12-31 に入った（`71b8e1b87`）。それまでの SCC はモノラルだったので、定位が入ったときに SCC の
電力が 2 倍になり、PSG との比が 12-23 に合わせた値から動いたことになる。`71b8e1b87` のコミット文は音量の変化に触れていない。
同じコミット文によれば、定位の値は Yamanooto の手引きの「66% / 33%」から取った。今の係数の振幅の比は 2.25 : 1（電力では 5 : 1）。
手引きそのものは読んでいない。

## 6. 差が無いもの

- 発音（`SCC::generateChannels`）、入力のサンプルレート（3579545 / 32 Hz）、波形と音量の掛け方（`(波形 × 音量) >> 4`）、周期 8 以下で
  止まる扱い、変形レジスタの bit0・bit1・bit5
- 電源投入時の値（波形 FFh、音量 15、周期 0）とリセット時の値（変形 0、全チャンネル無効）
- SCC の debuggable（モードによらず SCC+ の配置で見せる）

## 7. 読んでいて気づいたこと（比較の外）

1. **`-romtype Y8960Cartridge` で挿すと、0000-3FFF と C000-FFFF の読みでバンクレジスタの配列の外を引く**
   - `-carta` で挿した ROM は 0000-FFFF に置かれる（`HardwareConfig.cc:117-118`）
   - `peekMem`・`readMem`・`getReadCacheLine` は、番地の範囲を確かめずに `isRamRegion(address >> 13)` を呼ぶ（`Y8960Cartridge.cc:256, 269, 282`）。
     その先の `getBank(region)` は `bankReg[region - 2]`（`Y8960Cartridge.hh:61`）。region 0・1 では `unsigned` の引き算が折り返して
     約 4G 先を、region 6・7 では配列の 1〜2 バイト先を読む。書き込みの側は範囲を確かめている
   - `HRA_Y8960.xml` は 4000-BFFF にしか置かないので、拡張として使う限りこの経路は通らない
   - **確認済み**（2026-11-22、このコミットと読みの経路が同じ 11-19 のビルド）: `-machine C-BIOS_MSX2+ -carta <128kB の任意のファイル>
     -romtype Y8960Cartridge` で起動するだけで、エミュレーションの 0.1 秒の前に Segmentation fault で落ちた。デバッガは使っていない。
     直したあとの経過は `implementation-plan.md` §8 の (62)
2. **Yamanooto のデバッガからの読みは、FFFC-FFFF にもレジスタを見せる**（**未検証**）。`peekMem` はミラーしてからレジスタの番地を
   判定し（`Yamanooto.cc:144-147`）、`readMem` と `getReadCacheLine` はミラーする前に判定する（同 `:171, 186`）。CPU はそこで
   フラッシュを読む。`9a62047c7`（"config regs are NOT mirrored"）が直したのは `readMem` と `writeMem` で、`peekMem` は変えていない
